## ✨ این پروژه چیست؟

Alirezadns یک توزیع مستقل از [HyperDNS](https://github.com/IzumiRain/HyperDNS) است. کد اصلی برنامه دریافت و با تغییر نام نمایشی ساخته می‌شود؛ پنل جایگزین ساده‌شده یا قاب وابسته به نوا نیست. AdGuard، OpenVPN و نوا در این نصب قرار ندارند.

نام صفحه ورود، داشبورد، عنوان پیش‌فرض پورتال مشترکان و نوشته‌های مرتبط به **Alirezadns** تغییر می‌کند. نام‌های فنی پروتکل‌ها، API، پایگاه داده و سرویس `hyperdns` برای سازگاری حفظ می‌شوند. اطلاعیه‌های مجوز و نام توسعه‌دهندگان اصلی حذف نمی‌شوند.

## 🎛️ امکانات

- 🌍 DNS معمولی روی TCP و UDP پورت ۵۳، به‌همراه قابلیت‌های بومی DoH و DoT.
- 🎮 پراکسی SNI و مسیرهای بازی موجود در پروژه اصلی.
- 👥 مدیریت مشترکان، دسترسی‌ها، سهمیه‌ها و لینک‌های پورتال بومی.
- 🧩 سیاست‌ها و تنظیمات مسیریابی و resolverهای اصلی HyperDNS.
- 📊 آمار زنده، گزارش‌ها و ابزارهای تشخیص بومی.
- 🔐 ورود مدیر، قابلیت احراز هویت دومرحله‌ای بومی، API و مدیریت گواهی.
- 🎨 رابط اصلی، تم‌ها، فونت‌ها، زبان فارسی و انگلیسی؛ بدون حذف کنترل‌ها برای سبک‌سازی.
- 🔄 بررسی خودکار آپدیت، ساخت مجدد با نام Alirezadns و بازیابی از پشتیبان در صورت شکست بررسی سلامت.

عملکرد مسیرهای بازی و دسترسی به مقصدهای اینترنتی به شبکه، IP، سیاست‌های سرویس مقصد و تنظیمات شما هم وابسته است.

| مورد | نیاز |

| معماری | amd64 یا arm64 |
| دسترسی | root یا sudo |
| شبکه | IPv4 عمومی و دامنه با رکورد A مستقیم به همان IP |
| فضای دیسک | فضای کافی برای ابزار Go، کش ساخت و دو نسخه پشتیبان؛ حداقل ۸ گیگابایت فضای آزاد پیشنهاد می‌شود |
| حافظه هنگام ساخت | ۲ گیگابایت یا بیشتر پیشنهاد می‌شود؛ مصرف روی سرور یک گیگابایتی آزمایش نشده است |
| دسترسی خروجی | GitHub، مخازن سیستم‌عامل، proxy.golang.org، sum.golang.org و مرجع صدور گواهی |

پراکسی CDN دامنه را خاموش کنید. رکورد AAAA اشتباه می‌تواند صدور گواهی را مختل کند. پورت ۸۰ باید از اینترنت در دسترس باشد.

**روی سرور مستقل نصب کنید.** اگر نوا/alirezaserver یا نصب مستقل قبلی HyperDNS تشخیص داده شود، نصب متوقف می‌شود. سرویس اشغال‌کننده پورت‌ها خودکار حذف یا خاموش نمی‌شود. این نصب‌کننده ابزار مهاجرت از HyperDNS قبلی نیست.

## 🚀 نصب با یک خط

ابتدا فایل‌های `install.sh`، `setup.sh` و همین `README.md` را در ریشه شاخه `main` مخزن `alirezachatgpt97-coder/alireza-dns` قرار دهید. سپس روی سرور مقصد اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/alirezachatgpt97-coder/alireza-dns/main/setup.sh -o /tmp/alirezadns-setup.sh && sudo bash /tmp/alirezadns-setup.sh
```

اگر `curl` نصب نیست:

```bash
sudo apt-get update && sudo apt-get install -y curl ca-certificates
```

نصب‌کننده IP عمومی و دامنه را می‌پرسد، سورس و ابزار ساخت را دریافت و بررسی می‌کند، برنامه را می‌سازد، سرویس و فایروال را تنظیم می‌کند و منتظر سلامت HTTPS و DNS می‌ماند. **ساخت اول ممکن است چندین دقیقه طول بکشد**؛ در شبکه کند یا پردازنده ضعیف بیشتر طول می‌کشد.

راه‌انداز `setup.sh` هش همین نسخه از `install.sh` را کنترل می‌کند. هنگام انتشار، این دو فایل را با هم جایگزین کنید؛ نسخه‌های نامتناسب اجرا نمی‌شوند. نصب آنلاین است؛ هیچ‌کدام بستهٔ آفلاین نیستند.

## 📄 نصب مستقیم با یک فایل

فقط `install.sh` برای اجرای نصب کافی است:

```bash
sudo bash install.sh
```

برای ورود اطلاعات بدون پرسش تعاملی:

```bash
sudo env ALIREZADNS_HOST="YOUR_PUBLIC_IPV4" ALIREZADNS_DOMAIN="dns.example.com" ALIREZADNS_EMAIL="you@example.com" bash install.sh
```

مقادیر نمونه را با اطلاعات خود جایگزین کنید؛ ایمیل اختیاری است. رمز مدیر به‌صورت تصادفی ساخته می‌شود.

## 🔑 ورود به پنل

پس از نصب موفق، **آدرس دقیق و مخفی مدیریت، نام کاربری و رمز اولیه** در خروجی نمایش داده می‌شود. آدرس معمولاً چنین ساختاری دارد:

```text
https://YOUR_DOMAIN:8080/RANDOM_ADMIN_PATH/dash/
```

نام کاربری اولیه `admin` است. برای نمایش مجدد اطلاعات اولیه:

```bash
sudo bash install.sh --info
```

اگر رمز را داخل پنل تغییر دهید، خروجی `--info` همچنان رمز **اولیه** را نشان می‌دهد؛ از رمز جدید استفاده کنید. اگر مسیر مخفی یا پورت را داخل پنل تغییر دادید، آدرس جدید را نگه دارید؛ بررسی سلامت، اطلاعات مسیر و پورت را از سرویس می‌خواند، ولی اطلاعات نمایشی ذخیره‌شده ممکن است تا اجرای ترمیم قدیمی باشد.

## 👥 فعال‌کردن دسترسی مشتری

حالت پیش‌فرض، دسترسی محدود به کاربران مجاز است. در بخش کاربران پنل، مشترک بسازید و IP یا روش ثبت دسترسی بومی را تنظیم کنید. پاسخ `REFUSED` برای IP ناشناس به‌تنهایی نشانه خرابی DNS نیست.

IP سرور مقصد را به‌عنوان DNS مشتری تنظیم کنید. برای استفاده از DoH، DoT، پورتال و مسیرهای دیگر، آدرس‌های نمایش‌داده‌شده در راهنمای خود پنل را به کار ببرید. تنظیمات کامل پروژه اصلی در همان رابط موجود است.

## 🚪 پورت‌ها و فایروال

| کاربرد | پورت پیش‌فرض |
| --- | --- |
| DNS | 53 TCP و UDP |
| پراکسی HTTP و صدور گواهی | 80 TCP |
| پراکسی TLS | 443 TCP |
| پنل HTTPS | 8080 TCP |
| DoT | 853 TCP |
| DoH | 8443 TCP |
| مسیرهای بازی | 5222، 5223، 2099، 8393 TCP |

**برای همه امکانات، فقط بازبودن پورت ۵۳ کافی نیست.** نصب‌کننده قواعد اختصاصی `ALIREZADNS` را به فایروال سیستم اضافه می‌کند و قواعد نامرتبط را پاک نمی‌کند. فایروال شرکت میزبان یا Security Group باید جداگانه این پورت‌ها را مجاز کند. اگر پورت سرویس را از داخل پنل عوض کردید، فایروال آن پورت را هم تنظیم کنید.

## 🔄 آپدیت

هر شش ساعت نسخه جدید upstream بررسی می‌شود. نسخهٔ اولیه بر پایه `v2.2.0-beta.1` و سورس تثبیت‌شده در commit زیر ساخته می‌شود:

```text
4a899a90c682d14aa8fdc4506dd6efd84316956c
```

نسخهٔ جدید پیش از توقف موتور ساخته می‌شود؛ نام Alirezadns دوباره روی سورس اعمال می‌شود. نسخه اصلی متفاوت، کاهش نسخه یا تغییر ساختار شناخته‌شده ناسازگار رد می‌شود. سپس پشتیبان سرد گرفته می‌شود، فایل اجرایی و سورس متناظر جایگزین و سلامت سرویس بررسی می‌شود. در شکست بررسی، نسخه قبلی بازگردانده می‌شود. همه تغییرات احتمالی نسخه‌های آینده را نمی‌توان پیش‌بینی کرد.

اجرای دستی و تلاش مجدد برای نسخه ردشده:

```bash
sudo bash install.sh --update
```

دیدن تایمر و گزارش:

```bash
sudo systemctl list-timers alirezadns-update.timer
sudo journalctl -u alirezadns-update.service -n 80 --no-pager
sudo cat /opt/alirezadns-manager/update-status.json
```

فایل وضعیت پس از اولین تلاش برای تغییر نسخه ایجاد می‌شود. آپدیت موتور لزوماً به معنای آپدیت اسکریپت‌های ادغام نیست؛ برای نسخه جدید نصب‌کننده، فایل انتشار جدید را دریافت و `--repair` اجرا کنید.

## 🧰 ترمیم و بررسی سلامت

```bash
sudo bash install.sh --repair
sudo bash install.sh --check
sudo systemctl status hyperdns.service
sudo journalctl -u hyperdns.service -n 100 --no-pager
```

ترمیم نصب مدیریت‌شده، دیتابیس و کلیدها را نگه می‌دارد و سرویس را دوباره راه می‌اندازد. خطای دانلود یا ساخت پیش از تغییر فایل اجرایی متوقف می‌شود. شکست در مراحل ابتدایی اولین نصب ممکن است به بررسی فایل‌ها و گزارش نیاز داشته باشد؛ فایل‌های سرویس یا دیتابیس را برای رفع خطا کورکورانه حذف نکنید.

بررسی DNS، دریافت پاسخ از TCP و UDP را کنترل می‌کند؛ تضمین حل موفق همه دامنه‌های اینترنت نیست. برای تغییر دامنه یا DNS از پورت پیش‌فرض، تنظیمات عامل بررسی/آپدیت نیز باید با پیکربندی جدید هماهنگ شوند.

## 💾 فایل‌ها و پشتیبان

| مسیر | محتوا |
| --- | --- |
| `/opt/hyperdns` | موتور، دیتابیس، کلید، تنظیمات، گواهی و سورس متناظر |
| `/opt/alirezadns-manager` | عامل نصب/آپدیت، اطلاعات اولیه مدیر و کش ساخت |
| `/var/backups/alirezadns` | دو پشتیبان اخیر آپدیت |
| `/run/hyperdns/control.sock` | سوکت کنترل محلی مخصوص root |

پشتیبان‌های آپدیت جای پشتیبان خارج از سرور را نمی‌گیرند. برای snapshot سازگار، از امکانات میزبان یا کپی هر دو مسیر `/opt/hyperdns` و `/opt/alirezadns-manager` در زمان توقف سرویس استفاده کنید. کلید و دیتابیس را با هم نگه دارید؛ این فایل‌ها محرمانه‌اند.

## ⚡ مصرف منابع

ساخت با یک کار هم‌زمان و تنظیمات جمع‌آوری حافظه Go انجام می‌شود. گزینه‌ها، رابط و فونت‌ها برای کاهش مصرف حذف نشده‌اند. مصرف زمان اجرا به تعداد مشتری، ترافیک، کش و تنظیمات بستگی دارد؛ ظرفیت یک هسته/یک گیگابایت تضمین یا اندازه‌گیری نشده است.

## 📚 سورس و مجوز

پروژه اصلی [HyperDNS / IzumiRain](https://github.com/IzumiRain/HyperDNS) تحت **AGPL-3.0** است. این تغییرات هم با همان مجوز ارائه می‌شوند؛ اطلاعیه‌های اصلی محفوظ‌اند. سورس دقیق نسخه ساخته‌شده، شامل تغییرات و راه ساخت، در مسیر زیر برای کاربران قابل دانلود است:

```text
https://YOUR_DOMAIN:8080/alirezadns-source
```

پیوند دریافت سورس در صفحه ورود، داشبورد و پورتال نیز قرار دارد. این فایل از پوشه سورس ساخته می‌شود و شامل تنظیمات عملیاتی، دیتابیس و رمز مدیر نیست. برای ساخت دستیِ سورس دانلودشده:

```bash
CGO_ENABLED=0 go build -trimpath -o hyperdns ./cmd/hyperdns
```

نام فایل اجرایی فنی `hyperdns` حفظ می‌شود؛ نام پنل Alirezadns است. نصب این توزیع به معنای تغییر مالکیت یا حذف حقوق توسعه‌دهندگان اصلی نیست.
